# AITABLE 圓桌 004｜Koma 第一輪複審（715e562）

- **複審對象：** BBCODE1111/koma `main` 的 `715e562`（「Fix draft loss, interchange formats and mobile layout」）。對照的是初審報告 [aitable-004-review-e10781b-20261031.md](aitable-004-review-e10781b-20261031.md)。
- **確認線上版本：** 2026-10-31 約 02:05（台北時間）起，https://bbcode1111.github.io/koma/ 的 `index.html` 和 `715e562` 完全相同，`tests/test.html` 也回 200。當時 GitHub Pages／Actions 正處於「效能降級」，這次提交的部署紀錄卡在 waiting，但網站內容已經換成新版。
- **方式：** 沿用初審的 Playwright 測試腳本，用 headless Google Chrome 156 跑桌面 1440×900，手機用 iPhone UA 模擬 390×844 加觸控。我先在本機架同一份 commit 跑完一輪，線上更新後再對線上網址重跑；兩次結果一致（只有隨機產生的特效 id 和耗時不同）。
- **驗證工具：** FCPXML 用 Apple FCPXML 1.9 DTD 和 OpenTimelineIO 0.18 驗證，EDL 用 OTIO 的 CMX3600 解析器驗證。
- **沒辦法測的：** 真的 Final Cut Pro、DaVinci Resolve、Premiere、剪映匯入，以及實機 iPhone。

## 0. 先更正初審的一項結論

初審 P2-3 寫「手機版時間軸放大後無法用手指左右滑動（已實測）」，**這個結論的證據不成立**。

這次我做了對照組：在同一個測試環境裡，連「整頁上下滑」這種一定能捲動的操作，用 CDP 模擬觸控（`Input.dispatchTouchEvent`、`Input.synthesizeScrollGesture`，headless 和接 Xvfb 的有頭模式都試過）也完全不會捲動。換言之，這套環境模擬不出觸控捲動，初審拿它當證據是錯的。這一項應該改標「未驗證」，特此更正。

## 2. 重點測試

### 2.1 多份草稿還原
測過五條路徑：載入範例、貼上文字、選擇檔案、`drop` 拖放事件、新分頁開連結。每次換專案前都先改過原專案，換完後都能按「還原上一份草稿」拿回原專案和修改。

另外三點觀察：
- 沒有修改的專案不會留在備份裡。
- 還原時，目前這份如果有修改，會跟備份交換。
- 上限 5 份。超過時最舊的會被默默捨棄，按鈕也只顯示份數，看不出是哪個專案（見新問題 N4）。

整個過程沒有跳出任何確認對話框（測試都是單軌直切，不會觸發「不支援內容」的警告）。

### 2.2 影片起點 0.021 秒的一格誤差
用初審那支有起點偏移的檔案實測，`requestVideoFrameCallback` 的校正有效，所有抽查格位都正確。作為對照，起點為 0 的檔案 `vidOffset=0`，也正確。

### 2.3 FCPXML 和 EDL（7 種 fps）
每種 fps 都先做「c2 入點 +5、c4 出點 −6」再匯出：
- FCPXML：全部通過 1.9 DTD，沒有小數時間值，格數和 Koma 內部完全一致。
- EDL：OTIO 解析出的入出點也完全一致。
- 真實剪輯軟體的匯入**未驗證**。README 已經寫明「尚未在真實剪輯軟體上完成匯入驗證」，這點是誠實的。

### 2.4 手機觸控
- 點選鏡頭：可以。
- 按 ±1：可以。
- 拖修剪把手：可以，18px 等於 3 格。
- 左右滑動捲動時間軸：**無法驗證**（見第 0 節）。

### 2.5 手動操作清單：照著做會對嗎？
我讓 Koma 產生一份「只有修剪和刪除」的清單：c1 出點 −10、c2 入點 +5、刪掉 c4、在第 100 格加 Glitch。接著寫一個程式，**只讀清單上的文字**（時間碼和格數），由上往下照做，對測試成片 `render30b.mp4` 實際剪接。最後用 ffmpeg 抽出清單第二部分三個特效時間碼的畫面：

| 清單寫的 | 剪完後那一格的燒錄內容 | 應該是 | 結果 |
|---|---|---|---|
| 00:00:00 閃白 | OUT 000／c1 SRC 045 | c1 第 0 格（素材 45） | 正確 |
| 00:03:10 Glitch 抖動 | OUT 115／c2 SRC 253 | c2 第 38 格（素材 215+38） | 正確 |
| 00:05:27 RGB 分離 | OUT 192／c3 SRC 042 | c3 第 30 格（素材 12+30） | 正確 |

截圖：[照清單剪完後的三個特效格](aitable-004-rereview-1-shots/manual_follow_fx_frames.png)。「由後往前做」的設計確實讓前面的時間碼保持有效，總長也和 Koma 一致（219 格）。

另一份含「開頭延長 4 格」的清單，時間碼一樣正確。但手上只有成片的人做不到延長，因為成片裡沒有那段畫面（見新問題 N1）。

## 3. 新問題

**沒有新的 P0 或 P1。** 以下都是 P2：

- **N1　清單裡有「延長」時沒有提醒需要原始素材**（已實測）
  - 這份清單主要是給剪映這類不能匯入工程的使用者，而他們手上通常只有 Claude 給的成片，做不到延長。
  - 修法：遇到「延長」時標註「需要原始素材；只有成片的話請改請 Claude 重新輸出」。
- **N2　修剪步驟只給鏡頭範圍和格數，沒給實際下刀的時間碼**（已實測）
  - 例如「目前 00:00:00 到 00:02:12：結尾裁掉 10 格」，使用者得自己用 30 進位算出 00:02:02。
  - 修法：直接寫「在 00:02:02 切一刀，刪到 00:02:12」。另外「到」是不含終點的，也要寫明。
- **N3　時間碼格式只有三段**（未驗證）
  - Koma 用三段式「分:秒:格」，不確定剪映介面是否用四段式「時:分:秒:格」。29.97fps 下的對應也沒驗證。
  - 修法：改成四段時間碼，並註明幀率。
- **N4　草稿備份最多 5 份，超過時默默捨棄**（已實測）
  - 還原按鈕只顯示份數，看不出是哪個專案、什麼時間。
  - 修法：改成列出專案名和時間的清單；要捨棄最舊的一份時先提示匯出 JSON。
- **N5　test.html 沒有接進 CI**（已實測：repo 沒有 `.github/`）
  - Pages 部署前不會跑測試，壞掉的版本照樣會上線。
- **N6　手機頁首排版不整齊**（已實測，見手機首屏截圖）
  - 「重做」單獨佔一行，頁首比較鬆散，不影響功能。

## 5. 最終判定：能不能標「公開測試版」？

用我在初審提的收斂標準逐條對照：

| 條件 | 結果 |
|---|---|
| 沒有 P0／P1 | **符合**：初審的 P0、P1 都修好；P1-3 剩下的部分降為 P2（未驗證） |
| 自動檢查全過：FCPXML 通過 DTD、多種 fps 往返一致、桌面和手機流程 | **大致符合**：DTD 和往返全過，桌面全過；手機的觸控捲動在這套環境測不出來 |
| 至少在一套真實剪輯軟體（FCP 或 Resolve）匯入成功一次 | **不符合**：還沒做 |
| 每項 ≥ 7、平均 ≥ 8 | **不符合**：定位和程式碼品質各 6，平均 7.0 |

**結論：還沒收斂，但可以標「公開測試版」，不能標「穩定版」。**

理由：會造成資料遺失和畫面錯格的問題都已修好並實測確認，主要流程「修剪 → 修改清單 → 貼回 Claude」可以放心使用，README 也誠實寫明剪輯軟體匯入還沒驗證。

標公開測試版時，建議頁面上也寫明兩件事：
- FCPXML／EDL 尚未經真實剪輯軟體驗證。
- 手機觸控捲動尚未實機驗證。

下一輪要收斂，最少需要：
- 由使用者在 FCP 或 Resolve 實際匯入一次。
- 實機 iPhone 試滑時間軸。
- 修 N1、N2，讓手動操作清單能直接照做。
- 把 test.html 接進 CI。
